# muCommander - Two Panes Before You Copy

muCommander is a twin-pane file manager for directories you may use. The files are ordinary files. The panes only make the destination visible.

---

## Product Snapshot

Put the source on one side and the destination on the other. Confirm both paths. Copy a small file, then open it from the side that should have received it. Only then copy the rest. A move deletes from the source. If you are unsure, copy.

An FTP pane uses an address and a user you were given. Check the host. If the password fails, stop. Do not store it on a shared Windows login. Bookmarks from last week can point at a drive letter that has changed. Open the disk again instead of trusting the old bookmark.

## Highlights

- Two panes with paths you can read
- A one-file copy before the set
- Copy rather than move when you are unsure
- Bookmarks you recheck after a replug
- FTP only to your host
- System folders left out of the job

## Live Production

Use it to copy a project onto a spare disk you can name. Say the destination. Open the test file. A network folder that is asleep will hang a pane. Wake it or close the pane. Do not tidy another person's profile because both panes can see it.

Close muCommander on a shared PC. A stored FTP password would remain for the next login if you saved it.

---

## The Receiving Side

Click the destination pane and read it before you press the copy key. If both panes show similar folder names, check the drive letter in the path. The focused side is the one that changes. A bookmark is a shortcut, not a guarantee that the disk is still there.

---

## Setup Path

Prerequisites: Two folders you may use, with room in the destination.

1. Install muCommander and open the source and the destination.
2. Read both paths.
3. Copy one small file to the destination pane.
4. Open it there.
5. Copy the rest only if that file opened. Disconnect FTP when you finish.

## Who Benefits

muCommander fits a copy between two places you can explain. It does not fit system directories, someone else's files, a guessed server, or a move you start before the test file opens.

---

## Fixes

The file is in the wrong pane: you copied onto the source side. Read the path and put it back. FTP fails: stop, do not try other users. A bookmark opens the wrong disk: the letter changed. Browse to the drive again.
